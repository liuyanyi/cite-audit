# Cite-Audit UI / UX 指南

版本 2.0 · 2026-10-30 · Greenfield Remake · shadcn-admin 风格的简洁 CMS

> **设计目标**：结构像管理后台，阅读像专业工具。低干扰、信息充分、结论有据，作者能够从一份 Bib 逐层进入具体引用，再追溯至文章、版本与来源。

本指南与 [`DEVELOPMENT_GUIDE.md`](DEVELOPMENT_GUIDE.md)、[`DOMAIN_CONTRACT.md`](DOMAIN_CONTRACT.md) 及 [产品设计 v3.0](product/PRODUCT_DESIGN_v3.0.md) 配套。**这是全新界面实现规范，不保留或适配任何历史页面、组件、路由和状态模型。**截图是**视觉/布局参考，不是数据库事实或已实施交互**。用户最认可的风格基准为 [`00-visual-style-reference.png`](../references/00-visual-style-reference.png)；最新独立全页图提供信息模块基准。

## 1. 设计原则

**核心原则**：**Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.**

- **克制**：浅灰/白色背景、浅边框、短标题、紧凑表格、少量状态色。不要大面积彩色卡片、渐变、装饰图、重复说明。
- **完整**：简洁是减少无效层级，**不是减少专业信息**。引用详情必须保留原引用、当前版本核验、推荐版本、字段差异、版本关系、来源证据、原始 Bib、查询记录与安全导出入口。
- **层级明确**：默认是“上传的 Bib 任务列表”；进入一份 Bib 才展示“该次核查结果”；点击某一条才进入“引用详情”。知识库是另一个平行入口。
- **证据优先**：展示“核验事实”和“校订建议”之间的区别。不能靠彩色 badge 将有效预印本表现成错误，也不能让“来源有记录”自动变成“已核实”。
- **面向作者**：主要动作是上传、查看问题、比较证据、复制建议、导出新 Bib；不创建复杂的“已采纳/待复查/处理闭环”流程。
- **全新实现**：不要导入或兼容既有页面结构、组件和旧状态枚举。图片用于规范信息密度与视觉，而不是复刻生成图中的假操作。

## 3. 信息架构与导航

主侧边栏建议只保留：**核查任务、文献知识库、设置**。辅助的帮助与使用说明可以放底部，不将“引用核查”“书目校订”“修订复查”“统计分析”“报告”分别做成空的一级菜单。它们属于**单次核查任务内部**的功能。

```text
核查任务（默认页面）
  └── 某个 Bib 的任务详情
       └── 某条引用的完整核查详情
文献知识库
  └── 文章视图
       └── 版本详情 / 来源字段证据
设置
  ├── 数据源
  ├── 模型与密钥
  ├── 预算与调用审计
  └── 缓存/知识复用与运行设置
```

**导航行为**：点击条目进入独立 URL，刷新或分享本机链接仍处于该条目；面包屑能返回所属 Bib；“上一条 / 下一条”按当前任务中的列表顺序移动，保留原筛选条件。知识库条目的文章身份是全局 ID，与 citation key 无关。任务页和知识库页导航可以互相跳转，但从知识库打开文章不能修改正在核查的任务结论。

## 4. 基础视觉系统

### 4.1 设计 Token（推荐初始值）

以下值是根据参考图制定的**实施建议**，不是声称现有 shadcn-admin 模板已经使用这些精确数值。落地时统一抽象为 CSS variables/Tailwind theme，不把 HEX 分散硬编码在组件里。

| Token | 浅色主题建议 | 用途 |
| --- | --- | --- |
| `--background` | `#FAFAFA` | 应用背景 |
| `--surface` | `#FFFFFF` | 工作区、表格、普通面板 |
| `--text-primary` | `#171717` | 正文与主要标题 |
| `--text-secondary` | `#667085` | 附属内容、表格次要信息 |
| `--border` | `#E5E7EB` | 轻分隔与面板边框 |
| `--hover` | `#F5F6F8` | 行悬停、菜单悬停 |
| `--selected` | `#F1F5F9` | 选中行/左侧导航 |
| `--link` | `#2563EB` | DOI、官方链接、可点击证据 |
| `--success` | `#16A34A` | 已有足够证据的肯定结果 |
| `--warning` | `#D97706` | 可处理问题、待确认 |
| `--danger` | `#DC2626` | 明确冲突、错误与失败 |

推荐主操作按钮为深色实心（`#171717`），次操作为白底浅边框；蓝色主要用于链接、选中焦点和必要强调。**成功/失败颜色只能表示语义，不用于装饰**。在暗色模式下改用语义 token 派生，不直接复用这些浅色 HEX，保证列表行、边框、标签均有可辨对比度。

### 4.2 排版与密度

- 中文使用系统无衬线字体栈（如 `Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif`）；英文/DOI/Bib key 优先可读性，不强制引入外部字体下载。
- 桌面页面主标题约 **24–28px / 600–650**；模块标题 **15–17px / 600**；正文与表格 **13–14px**；辅助文字 **12px**。不要用五六级标题堆叠提示。
- 采用 **4px 基准间距**：常用 `8 / 12 / 16 / 24`；侧边栏宽 **200–228px**，顶栏高 **56–64px**，主内容水平留白 **24–32px**。
- 标准表格行高建议 **42–48px**；长标题可两行展示或 tooltip 完整展开，不能为追求单行而省略关键信息。
- 面板圆角 **6–8px**，边框 1px；尽量取消阴影或只用极轻阴影。层次靠留白、分栏、细分割线，不靠“卡片里面再套卡片”。
- 区块内短标签遵循统一左右对齐；数字和日期使用 tabular numerals，避免刷新进度时列宽跳动。

### 4.3 交互基线

按钮有真实动作，不出现视觉上可点但没有后端效果的“采纳/刷新/添加”按钮。状态标签不伪装成按钮；详情行、证据链接有清晰 hover/focus。加载、空结果、异常、部分结果、网络受限、演示模式有明确样式，不把空白当成“没有错误”。

## 5. 页面一：Bib 核查任务列表

参考图：[01-bib-task-list.png](../references/01-bib-task-list.png)

**职责**：管理每一次 Bib 上传产生的独立核查任务。默认打开此页，**不是**直接打开某个任务的引用表。

**页面结构**：顶部标题“Bib 核查任务”与显著“上传 Bib 文件”；下方是紧凑的搜索/筛选栏和任务表格。是否显示摘要数字可根据真实任务量决定；若保留，限制在一行并弱化装饰。与参考图 00 一致，主视线应该落在**文件列表**。

| 区域 | 保留信息/交互 |
| --- | --- |
| 任务行 | 用户可设的任务名称（没有则用文件名）、文件名、条目数、**执行状态**、开始与更新时间、可见的问题计数 |
| 搜索/筛选 | 按任务名和 `.bib` 文件名搜索；按执行状态、创建日期排序/筛选 |
| 行操作 | 进入任务详情、查看报告、在明确二次确认后删除本次任务（不删除共享知识） |
| 上传操作 | 选择 Bib、检查名称/编码/大小/条目数、选择演示/在线和本次配置、提交后跳转新任务 |

**必要修正**：任务状态只表示 `排队中 / 核查中 / 已完成 / 部分完成 / 失败 / 已取消` 等**执行状态**；“存在问题”属于**结果摘要**而不是与“已完成”互斥的运行状态。相同文件再次上传应创建独立行，不默认为复查任务。

## 6. 页面二：单次 Bib 任务详情

参考图：[02-bib-task-detail.png](../references/02-bib-task-detail.png)

**职责**：展示这次上传了什么、检查进行了多少、整份文件中哪些引用需要关注；点击后进入单条详情。不能把上一页的多个 Bib 数据混在这里。

**固定信息骨架**：

1. **面包屑与文件头**：`核查任务 / 某任务`，任务名称、`.bib` 文件名、原始条目数、上传时间、执行状态；上传原件下载/查看、导出报告、新文件校订入口在右侧（视能力与状态显示）。
2. **紧凑的结果摘要**：总条目、核查完成数、明确冲突条目数、身份未决条目数、执行失败/未检查条目数。建议升级与可补全可以是**次级标记**，不可与核验结果相加当作互斥状态。
3. **条目列表**：citation key、完整可展开标题、第一作者、原年份、事实核验结论、主要建议类型。状态列和推荐列必须分别显示：`已核实 + 建议正式版` 可以并存。
4. **表格工具栏**：标题/key/作者搜索、状态筛选、建议类型筛选、排序、问题条目快捷筛选。统计按真实数据计算且说明已检查覆盖率。
5. **运行和报告**：选项卡或轻折叠区呈现来源调用概况、失败原因、调用审计与成本；不占用默认表格的主要空间。

**结果标签语义**：`已核实` 不能表示所有字段都验证完毕；`存在字段冲突` 表示确证；`身份待确认` 表示没有足够证据；`来源失败` 表示执行异常。推荐正式版仅是建议，不应自动升级为红色错误。

任务结束只说明全部可执行流程结束，**不代表所有文献都真实**。表格行应支持“上一条/下一条”顺序导航，并在刷新后保留页面/筛选状态。

## 7. 页面三：引用核查详情（信息完整性重点）

参考图：[03-citation-detail.png](../references/03-citation-detail.png)

**这是不能删减的主业务页面**。建议采用“左侧主证据工作区（约 65–70%）+ 右侧来源证据（约 30–35%）”的桌面布局；左右各自可滚动，但不能把左侧表格压得无法阅读。窄屏应改为上下布局。

### 7.1 顶部：这条引用当前是什么

标题、citation key、原条目类型、原年份、当前 DOI/标识符、原文件来源、核查结论、建议类型和上一条/下一条导航。顶部明确区分：

- **当前引用**：用户 Bib 真正写了什么；可能是有效的 arXiv 预印本。
- **当前版本的核验结论**：是否找到对应出版记录，哪些字段正确或错误。
- **默认推荐版本**：属于同一 Article 的、可以建议替换的版本；在证据不足时不一定存在。

**不允许**在推荐会议版时，把有效 arXiv 的 2018 年/预印本 DOI 直接涂红为“错误”；它们是**跨版本差异**。

### 7.2 字段对比：区分两种比较对象

强制提供两个清楚的比较上下文，避免“错误”和“建议升级”混淆：

| 比较模式 | 左列 | 右列 | 判定列 |
| --- | --- | --- | --- |
| **当前版本核验**（默认） | 上传 Bib 的原值 | 已确认的**当前版本**整合值 | 一致 / 明确冲突 / 可补全 / 未核实 / 不适用 |
| **推荐版本差异** | 上传 Bib 的原值 | **推荐版本**整合值 | 保持 / 版本切换需要改变 / 目标版本待核 |

两种模式使用相同表格骨架：字段、当前值、对照值、判断、依据。字段包括 `entrytype, title, author, year, doi, journal/booktitle, volume, number, pages/article-number, publisher, url, eprint` 等适用字段；特别长的 `booktitle` 和作者可折行、复制、展开，不靠大量截断减少高度。点击判断/依据可在右侧定位对应来源内容。

**颜色规范**：当前版本的确证字段冲突可用红色；有效预印本与推荐会议版之间的差别采用中性色/提示色，文案写“改用推荐版本时需更新”，不写“年份错误”。

### 7.3 版本关系

字段表下方保留完整的**版本关系区**。默认突出当前版本与文章推荐版本两个对象：各自标题/年份/类型/出处/DOI/URL、关联依据，以及“推荐与当前引用是否为可替代版本”。若存在更多版本，在折叠列表或跳转知识库中展开，不让小差异的数据源假装成多个版本。

**推荐的行为**：`修正当前版本` 与 `整体改用推荐版本` 两个提案属于不同动作。跨版本切换必须走整体一致性检查；需要明确确认，不能把预印本 DOI 保留在会议版 `doi` 字段。

### 7.4 右侧来源证据

每条来源卡应显示来源名、**关联版本**、来源类型（官方/注册机构/聚合/人工未核验等）、原始链接、获取/复核时间、字段覆盖、关键提取字段和与当前判断的关系。来源卡可以折叠原始字段；一个版本可有多个来源，来源数不能自动成为独立证据数。

证据与字段应**双向跳转**：表格点“依据” → 对应 SourceContent + 字段；来源卡点字段 → 高亮表格行。来源不可访问时显示保留的历史快照和复核状态，不能空白后仍写“已确认”。

### 7.5 原始条目、建议 Bib 和操作

**所有关键信息都必须在新详情页可访问**：原始 Bib、当前版本修订 Bib、推荐版本 Bib、候选、查询记录、未解决原因至少通过页内区块/次级标签可访问；较技术性的查询日志可以折叠，但不能只剩三张来源卡。推荐 BibTeX 只由有证据的结构化字段序列化生成。

主要操作按顺序：复制建议 BibTeX、复制字段、查看官方来源、返回任务。**整库导出**在任务侧提供：本任务选择修订条目/字段 → 预览差异和未决项 → 明确确认 → 生成**新文件**；任何按钮都不能直接覆盖上传文件或改变知识库推荐指针。

## 8. 页面四：文献知识库（文章视图）

参考图：[04-knowledge-base.png](../references/04-knowledge-base.png)

**目的**：查看系统已经积累哪些文章、哪些版本、版本由哪些源内容归并而成；这是证据查询与诊断页，不是另一个供用户逐条“采纳”的审核后台。

采用可调整宽度的**三栏**：

| 左侧：Article 列表 | 中间：文章/版本 | 右侧：源内容 |
| --- | --- | --- |
| 标题/作者/标识符搜索；每行是**文章实体**，不是版本/来源 | 文章标题与作者摘要；推荐引用版本；其余版本及版本身份；当前选中版本的整合字段/冲突 | 当前版本对应各 SourceContent；来源、原始值、URL、时间、状态、字段证据 |

Article 默认推荐版本卡只呈现**一条主要推荐**，版本列表可显示预印本、会议版、期刊版等**真实不同出版身份**。同一会议版来自 Crossref、ACL、OpenAlex 的记录应出现在**右侧来源列表**，不能在中间成为三个版本。

中间版本详情可切换：`整合字段 / 字段冲突 / 版本关系`。字段冲突展示多个来源值、采用值、理由和未解决项。右侧来源按身份/权威类型清楚标注，提供快照、刷新状态与外链；“来源更多”不等于“结果一定正确”。

**交互边界**：不默认展示“收藏”“已采纳”“引用次数/推荐热度”等无关概念；不提供无证据的一键新建**确认版本**或点击改变全局推荐。人工资料导入若保留，仅作为“待核线索”单独标记。知识库推荐是派生选择，变化应来自新来源/规则，不能来自某次任务里的操作。

## 9. 设置：作为辅助能力，不抢占主流程

参考图：[05-settings-secondary.png](../references/05-settings-secondary.png) 仅供分组参考；视觉要回归 00 的克制样式。

在单个设置页面用少量标签或分区组织：数据源启停及连接测试、模型/密钥、请求/成本预算、缓存与知识复用、调用日志。正确区分：无 Key 来源、需要 Key 的来源、有机构授权的来源，以及仅计划接入的来源；**未实现的连接不显示“正常”**。

成本数字有来源和币种；无法估算时显示“未知”而非 `$0`。测试连接可能真实联网/计费，需清楚提示。密钥不回显，日志脱敏。清除查询缓存与删除知识/任务不是同一动作，不应共用一个危险按钮。

## 10. 推荐组件与工程实现

界面从零搭建，风格参考 shadcn/ui + shadcn-admin 的布局与交互，但不要复制其完整演示后台或预置权限/用户系统。推荐采用 React + TypeScript、shadcn/ui + Tailwind CSS；表格/路由/请求状态可使用成熟第三方库。组件职责应以本产品新领域契约组织，不映射到任何历史 React 组件。

| 功能 | 推荐的组件模式 | 说明 |
| --- | --- | --- |
| 页面布局 | `AppShell`, `Sidebar`, `Topbar`, `Breadcrumb` | 所有页面共用一个 Shell，菜单层级少 |
| 任务及条目 | `DataTable`, `Toolbar`, `Pagination`, `EmptyState` | 表头稳定，搜索/筛选/排序明确 |
| 事实状态 | `StatusBadge`, `EvidenceLink`, `ProgressSummary` | 颜色与语义绑定，不能靠颜色单独传达 |
| 证据 | `EvidencePanel`, `SourceRecordCard`, `FieldEvidenceRef` | 字段→来源精确定位，支持长内容 |
| 版本 | `VersionSummary`, `VersionRelationship`, `RecommendedVersionCard` | 推荐一条，其他版本按需展开 |
| Bib 原文/导出 | `BibCodeView`, `DiffView`, `ExportReviewDialog` | 可复制、格式保护、明确的导出确认 |
| 系统反馈 | `Skeleton`, `InlineError`, `Toast`, `ConfirmDialog` | 原因具体，不做假成功提示 |

不建议单个入口组件承载全部复杂交互，也不建议把每个字段切成极小组件导致理解成本膨胀。以新页面和少量稳定交互组件组织；样式 token、状态含义和字段证据引用统一管理。**无需建设任何旧 UI 适配层。**

## 11. 响应式、可访问性与边界情形

| 场景 | 要求 |
| --- | --- |
| **1440px 及以上桌面** | 完整侧栏与表格，引用详情主区/证据双栏；知识库三栏。建议首要验收视口 1440×900。 |
| **1024–1439px** | 导航可收窄，任务表隐藏非必要列但保留行详情；引用页面可将来源变成可打开的侧面板。 |
| **平板/窄屏** | 表格在受控容器内横向滚动或切换紧凑列表；知识库一栏一层，不让截图式全宽界面溢出。 |
| **深色模式** | 使用 token 切换，保证灰字、边框、Badge、表格行/hover 对比；不能让红绿标签成为唯一状态信息。 |
| **长作者/长会议名** | 折行/展开/复制，不截断关键 DOI 或证据链接；引用原文用代码区水平滚动。 |
| **加载与部分完成** | 展示骨架/局部进度；部分结果保留，来源失败单独提示；不因单条失败使整页清空。 |
| **键盘与读屏** | Tab 顺序、focus ring、按钮 aria-label、表格标题、对话框焦点管理、列表选中状态；WCAG AA 对比度作为最低目标。 |

## 12. UI 验收清单

- [ ] 视觉对齐 **00 风格参考**：浅色、细边框、紧凑表格、少卡片、少重复副标题。
- [ ] 页面是**四张独立全页**：任务列表 → Bib 任务详情 → 引用详情；知识库独立入口。
- [ ] 上传同一 Bib 两次是两条不同任务；从任务列表能进入指定 Bib，而不是默认展示第一份 Bib。
- [ ] 一条引用的原 Bib、核验结论、字段对比、版本关系、推荐 Bib、来源证据、查询记录**都可访问**。
- [ ] 有效预印本与正式版差异不会被 UI 标成原字段错误；两个比较上下文可辨认。
- [ ] 字段和证据双向可定位；来源失效、冲突、未核实状态不会被隐藏。
- [ ] 知识库以 Article 为列表行，同 Version 的多源信息在 SourceContent 区归并呈现。
- [ ] 全部计数和百分比真实一致；执行完成、引用真实性、校订建议三维清晰。
- [ ] 列表/详情在加载、无结果、异常、演示、长文本、窄屏、深色模式下可用。
- [ ] 导出明确生成新文件；没有一个 UI 按钮可以修改原始 Bib 或把作者选择写入共享事实。

最后的设计判定标准：**作者不需要理解底层 Provider，也能知道哪条引用可靠、哪里有问题、建议怎么改、每个结论来自哪里。**


## 13. UI 开发的最终交付检查

本轮是**新代码实现**，因此首张完整截图只能证明视觉方向，不能替代可交互验收。请为任务列表、单次 Bib 详情、引用核查详情、文章知识库各准备**独立的 1440×900 或更大截图**，并使用真实接口契约驱动的测试数据验证加载、点击、筛选、证据跳转和导出。若使用离线 fixtures，明确呈现“演示数据”状态。

开工顺序建议：先完成共享 AppShell 与样式 token，随后做任务列表、单次 Bib 详情；完成领域模型与核查状态接口后再做完整引用详情；最后实现文章三栏视图和设置。不得仅按参考图静态排版，也不得在 UI 里缓存或构造“看起来已验证”的假结论。

**重要设计优先级**：领域事实正确 > 页面含义和交互正确 > 四张完整界面的信息完整性 > 用户认可的克制型视觉基准 > 参考图里的虚构内容。

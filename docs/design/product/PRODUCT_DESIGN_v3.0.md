# Cite-Audit 功能与设计说明

版本：3.0  |  日期：2026-10-30  |  状态：全新实现的产品与领域设计基线

## 01  产品定位与功能架构

面向论文作者，在写作过程中审阅整份 BibTeX 文件，核实引用对象、发现书目信息错误，并提供有来源依据的校订建议。

产品交付的是一份可审阅的整库核查结果：每条引用定位到了什么文献、哪些字段得到验证、哪里存在冲突、默认建议采用哪一份记录，以及尚有哪些信息不能确认。目标是降低幻觉引用风险，不以一次搜索未命中宣判文献不存在。

### 功能架构

| 层次 / 模块 | 承担的职责 | 对作者的主要产出 |
| --- | --- | --- |
| 管理：核查任务 | 接收整份 Bib，组织执行、历史与结果。 | 全库概览、问题列表、任务报告。 |
| 业务：引用核查 | 确定文献与版本身份，核对当前引用。 | 身份结论、字段冲突、未决项与证据。 |
| 业务：书目校订 | 纠错、补全、规范化，并提供推荐版本。 | 字段差异与可复制的建议 BibTeX。 |
| 基础：文献知识库 | 按文章—版本—源内容积累、归并信息。 | 可复用的文献事实和默认推荐版本。 |
| 辅助：设置与日志 | 配置来源、模型、预算、缓存与调用记录。 | 可控的访问、成本和故障信息。 |

### 设计定论

全库审阅归入任务与结果管理，不单列为核心业务；不建立独立复查模块，再次上传即创建新核查任务。不同任务共享来源知识，不继承“上次通过”或作者的采纳、忽略等决定。

> 知识库采用“文章 → 版本 → 源内容”。同一版本可以由多个源内容归并得到；文章指向一个默认推荐版本；不同发表版本之间不拼接书目信息。

### 范围边界与设计依据

原始 Bib 保持只读。不核验正文论断是否被原文支持，不默认下载全文，不建设论文推荐、文献阅读或多用户协作系统。产品优先覆盖期刊论文、会议论文和预印本；其他文献类型按适用字段核验，覆盖不足时说明限制。

本稿为独立、完整的产品设计基线，**不依赖任何历史代码、数据库、API、页面或缓存结构**。开发从空白实现开始，可自行选择符合本设计的技术方案；不编写兼容旧版本的数据迁移器、接口适配层或旧页面复刻。先前视觉图仅用于理解设计风格与信息结构，不能作为业务真实数据。本文不代表任何代码或外部数据源已经实现或实测。


## 02  作者流程与核查任务管理

> 上传 Bib → 启动核查 → 浏览整库结果 → 查看差异与证据 → 复制建议并修改本地文件。再次上传时，从同一入口创建新任务。

### 输入与任务边界

接收完整 Bib 文件，保存不可变的上传快照及条目原文。解析全部条目，保留 citation key、字符串宏、交叉引用和自定义字段；无法处理的结构明确报告，不静默跳过。某个条目解析失败不应阻止其他条目继续检查。

每个任务独立保存输入、配置、执行状态、核查结果和所用证据快照。新任务无需关联父任务，也无需作者声明“这是复查”。相同条目可复用知识库中的事实，但必须针对本次输入形成结论。

### 整库结果的组织

| 区域 | 必须回答的问题 |
| --- | --- |
| 任务概览 | 共收到多少条？完成、未完成和解析失败各有多少？哪些条目有明确冲突或仍待核实？ |
| 文献列表 | 每个原始条目一行：citation key、标题、主要结论、建议类型及执行情况；按问题重要性排序。 |
| 筛选与搜索 | 支持按 key、标题检索，按冲突、身份未决、版本建议、补全建议、未完成等筛选。 |
| 跨条目检查 | 提示重复 key、同一版本重复收录、同一标识符对应矛盾条目、预印本与正式版的潜在重复。 |
| 历史任务 | 回看当时的文件、结果、配置与证据。新知识不能悄悄改写旧报告。 |

重复条目只提示，不自动删除或合并用户文件中的记录。仅有 Bib 输入时，不判断哪些条目未被正文引用，也不将预印本比例或缺少 DOI 直接转换成质量分数。

### 状态保持简洁

执行状态表达排队、执行中、完成、部分完成、失败或取消；核验结果表达事实是否确定；校订建议表达可采用的改动。三者分开，不引入“已采纳 → 待修改 → 待复查”状态机。

概览应明确哪些计数互斥、哪些标签可以重叠，避免将同一条引用的多个问题重复计入“问题条目数”。“任务完成”只说明流程结束，不代表所有引用和字段均已验证。

### 任务生命周期与再次上传

未结束任务支持刷新页面、进程重启后恢复，并可取消或重试失败请求。作者再次上传文件**始终创建独立任务**，不需要定义“复查”类型，也不要求父子任务链。知识库可按需在后台更新来源记录，但本次已输出的核查报告必须固定证据版本；任何需要给作者形成一份新结论的重新核查，都应形成新任务，不覆盖旧报告。


## 03  核心业务：引用核查

核查回答两个问题：当前条目究竟指向哪篇文章的哪个版本？在该版本下，条目中的信息是否有依据？

### 文献身份与版本归属

以标识符、标题、作者及出版信息联合匹配。输入 DOI 仅是待核线索：若它指向另一篇论文，应报告归属冲突，并继续用标题和作者定位原本可能引用的文献，不据此把整条引用替换为错误 DOI 对应的论文。

先确定文章和所指版本，再核验字段。发现相似论文只能生成候选；文章归属、版本归属或候选关系无法确定时，保留未决状态，不使用“最像的一篇”自动补成完整记录。

### 核验范围

| 检查对象 | 判断重点 |
| --- | --- |
| 标题与作者 | 题名是否对应；作者及顺序是否一致；缩写、转义、大小写与实质差异分开。 |
| 发表信息 | 期刊或具体会议论文集、年份、卷期、页码或文章号是否属于当前版本。 |
| 标识符与链接 | 格式、可解析性、文献归属及版本归属逐层核实；缺少 DOI 不自动判错。 |
| 条目完整性 | 识别来自不同论文或不同版本的字段拼接；区分错误、缺失、未验证与不适用。 |
| 出版状态 | 对已接入且有证据的更正、撤稿等状态作提示；未查询到不等于已经排除。 |

### 面向作者的结论

| 结论类型 | 呈现方式 |
| --- | --- |
| 已核实 | 明确文献身份、匹配版本及实际验证的字段；未验证字段仍可展开查看。 |
| 存在明确冲突 | 指出原值、依据值、冲突性质与来源；不直接泛称整篇论文“虚构”。 |
| 未核实或有歧义 | 列出缺少的证据、候选及已检查范围；不生成无依据的确定性替换。 |
| 检查未完成 | 说明网络、权限、预算、来源失败或取消等原因，与“搜索无结果”分开。 |

模型可协助候选消歧、网页字段抽取和解释，但必须引用实际取得的源内容。模型记忆、主观置信度、检索摘要及多个聚合站点的重复转载，都不能单独构成充分的事实核验。


## 04  核心业务：书目校订

默认提供一条明确的主要建议。正常情况下，建议使用文章的推荐版本及其整合后的书目记录；其他版本与源内容放在详情中。

### 三类校订分别表达

| 类别 | 含义 | 输出规则 |
| --- | --- | --- |
| 纠错 | 当前引用字段与已确认版本冲突。 | 给出建议值、差异和证据。 |
| 补全与规范化 | 补充有依据的缺失信息，统一等价表达。 | 不把可选字段缺失或等价格式当成真实性错误。 |
| 发表版本建议 | 当前版本有效，但文章存在更适合默认引用的版本。 | 说明版本关系，展示整条替换建议，不否定原版本真实性。 |

### 原引用核验与推荐版本分开

有效的预印本不能因为推荐版本是会议版，就被标成“年份错误”或“文献类型错误”。详情先说明当前版本是否成立，再说明是否建议切换。当前版本自身也有字段错误时，区分“修正当前版本”和“切换至推荐版本”，默认主要建议仍保持唯一。

### 版本切换必须保持记录一致

同版本纠错可逐字段采用；跨版本切换按出版记录整体替换。标题、作者、条目类型、年份、出处、DOI、页码及版本专属标识符须保持同一版本归属，不允许通过任意勾选拼成混合引用。目标版本未确认的字段留空或标为待核，不从原版本补入。

保留原 citation key、必要的大小写保护、中文和 LaTeX 转义，以及不冲突的自定义字段。旧版本的 DOI、URL、eprint 等应按目标版本语义移除或迁移；原预印本链接可作为关联信息保留，但不能冒充正式版 DOI。

### 作者可获得的结果

提供字段对照、推荐记录、事实证据、版本关系理由，以及复制单个字段和单条建议 BibTeX。整库报告保留未决项与检查覆盖范围。建议由已核实的结构化字段序列化生成，不让模型自由重写整份 Bib。

整库“建议 Bib”可作为可选输出：须经作者明确确认后生成新文件，不覆盖上传原件。它不是本版新增的强制前置功能；有未决项时应保留原条目并附修改清单，不静默丢弃。

### 用户操作不改变事实

复制、采纳、忽略或选择保留预印本，都不改变核验结论和共享知识。如果界面需要记住当前选择，只放在本次任务或导出草稿中，不据此修改文章的推荐版本，也不跨任务继承为事实。


## 05.1  文献知识库：文章—版本—源内容

> 文章负责关联版本与指定推荐；版本负责形成一致的书目记录；源内容负责提供可追溯的事实依据。

| 层次 | 定义 | 最小保存内容 |
| --- | --- | --- |
| 文章 Article | 同一研究成果的组织主轴。 | 内部 ID、已确认版本、推荐版本引用、版本关联依据。 |
| 版本 PublicationVersion | 一份可辨认、可引用的发表或具体修订记录。 | 内部 ID、版本类型与标识符、整合字段、字段来源、冲突、记录修订号。 |
| 源内容 SourceContent | 某个信息源对该版本的描述。 | 来源及源记录 ID、原始内容或可保留快照、提取字段、来源链接、获取时间与内容摘要。 |

### 关系与边界

一个文章关联多个已知版本，并有零个或一个生效的默认推荐版本。一个版本可关联多个源内容。已归属的源内容进入对应版本；待确认的源内容保留待匹配状态，不为方便存储而创建“已确认版本”。“已知版本”不承诺穷尽该文章的全部发表历史。

源记录的再次抓取形成证据快照；版本字段的重新归并形成整合记录修订。二者都不自动创建新的发表版本，也不增加第四个业务层。显式的 arXiv 修订号等具体内容版本标识应保留，不与抓取时间混淆。

### 版本不是某个来源的别名

同一会议版可同时对应官方论文集、注册机构和聚合数据库的源内容。版本层以这些记录形成完整书目数据；它不等于其中某一个来源，也不因来源数量而重复创建。推荐引用指向版本对象，而不是临时选中的来源或另存的一份 BibTeX。

若一个聚合响应同时描述预印本与正式版，应按发表对象提取相应源内容，引用同一原始响应。无法拆清的字段保留待核，不能把全部字段复制到两个版本，也不能因一个聚合 ID 相同就把两个版本合并。

### 事实与派生信息

知识库保存来源事实，以及有证据支持的版本归属、字段合并和推荐选择。派生记录应标明依据及规则版本，允许重新计算。原始源内容不因合并而被覆盖；再次计算时回到来源证据，不能把旧的合并结论当成独立证据自我证明。

用户 Bib 原文、输入错误、采纳或忽略决定、上次核查是否通过，均不进入共享文献事实层。作者提交的 URL 或人工题录只能作为线索或明确标记的材料，未经核实不能伪装成系统已在线确认的来源。


## 05.2  版本去重：先确认身份，再处理差异

多个源内容有小幅差异，不足以创建多个版本。版本去重依据发表对象的身份；字段差异由同一版本内部的合并与冲突处理承担。

| 证据或差异 | 处理规则 |
| --- | --- |
| 规范化 DOI 或官方记录 ID 相同 | 结合题名、作者和出版信息排除明显矛盾后归并；不信任未经核实的输入标识符。 |
| ID 不齐，但出版记录互相印证 | 用标题、作者、具体论文集、年份和页码等组合确认；仅标题相似不够。 |
| 大小写、标点、转义、姓名缩写、会议简称 | 保留原文，生成比较用规范形式；等价表达不拆版本。 |
| 一处缺页码，另一处提供页码 | 确认同版本后补全；空值与信息完整度差异不拆版本。 |
| 已确认同一记录，但年份或页码冲突 | 留在同一版本中处理冲突；先区分上线日期、正式出版日期等字段含义。 |
| 预印本与正式会议出版记录 | 存在不同发表身份时建立不同版本；确认属于同一研究成果后关联文章。 |
| 期刊扩展、后续研究、勘误通知 | 不自动当作可替换版本；实质独立成果保留为关联文章，关系不足时暂不合并。 |

### 两次身份判断，两个不同问题

版本归并回答“这些源内容是否描述同一发表记录”；文章关联回答“不同发表记录是否属于同一研究成果”。两者不能共用一个标题相似度阈值，更不能把“标题相近”直接等同于“可以互相替换引用”。

标识符不同不必然是不同版本，标识符相同也需要排除错误绑定。标识符必须保存命名空间、来源及对象类型，区分文章级聚合 ID、版本 ID 与具体源记录 ID。

### 防止误合并扩散

自动归并需有充分身份依据。弱相似关系不可链式传递：A 像 B、B 像 C，不足以将三者全部合并。每条归属和文章关联均可追溯，发现错误时允许拆分、更正并重新计算受影响版本。

更正当前知识库不能改写历史任务当时的证据快照。来源不一致、关系不明或匹配未决时，宁可保留候选，也不能靠拆出多个“版本”掩盖冲突，或靠合并消除差异。


## 05.3  同版本源内容合并与字段证据

> 允许“同一版本的多个源内容 → 一份整合记录”，禁止“不同版本的字段 → 一份混合记录”。归属确认必须先于字段补全。

### 合并规则

| 差异类型 | 整合动作 | 需要保留的依据 |
| --- | --- | --- |
| 等价表达 | 统一比较或显示形式，不制造错误。 | 原始写法、规范化方式及源内容引用。 |
| 信息互补 | 补入经确认属于同版本的缺失字段。 | 采用值、来源位置与版本归属证据。 |
| 实质冲突 | 按字段含义和证据质量选择采用值；无法判断则保留未决。 | 不同取值、来源、选值理由及未解决冲突。 |
| 缺失或未提供 | 保持未知，不凭记忆补全。 | 缺失状态；必要时触发针对性补查。 |

### 选值依据不等于来源投票

优先考虑与该版本直接对应、明确表达该字段的来源；结合官方出版记录、字段完整性、修订情况及其他证据判断。不同字段可以采用不同源内容，不设一个盲目的全局覆盖顺序；来源数量和抓取时间不能单独决定正确性。

记录可识别的上游来源链。多个数据库转述同一上游记录不算多份独立证明；“刚抓到”只说明获取时间近，不说明出版记录更新，也不说明内容更正确。

### 复合字段保持整体一致

作者列表按顺序作为整体核验，不把不同来源的作者做集合并集。页码与文章号、期刊与会议、上线日期与卷期日期、论文级与论文集级标识符应先分清语义，再进行比较。来源之间不同的省略方式不自动成为作者缺失错误。

### 整合记录至少保留什么

| 字段信息 | 含义 |
| --- | --- |
| 采用值与状态 | 当前使用的值，以及已确认、存在冲突或未确认等状态。 |
| 支持证据 | 源内容 ID、对应快照及字段位置；必要时记录提取方式。 |
| 其他取值与处理理由 | 哪些来源存在不同描述，为什么采用或暂不采用。 |
| 整合修订与规则版本 | 哪些来源与规则产生了该结果，便于解释、重算与历史回看。 |

示例（虚构）：来源 A 提供某会议版的完整作者与页码，来源 B 补充经核实属于该会议版的 DOI，来源 C 使用会议简称。三者归入同一版本；整合记录使用 A 的作者与页码、B 的 DOI，并规范化出处。若 C 给出不同页码，应作为该版本的冲突保留，而非新建版本。


## 05.4  默认推荐版本

每篇文章通常维护一个默认推荐引用版本。推荐直接指向已有的整合版本对象，不另建“综合推荐版”，不把多版本选择压力默认交给作者。

### 推荐规则

前提是文章与版本关系已经确认、该版本身份可信，且具备可支持引用的记录。存在可替代的正式发表版时，默认优先于预印本；未发现可确认的正式版时，可推荐已核实的预印本。没有 DOI 不构成排除条件。

不简单按年份最新、期刊高于会议或来源数量排序。内容明显扩展的期刊论文与后续研究不自动取代原会议论文；针对同一平台的主会、Findings、Workshop 或投稿记录，需保留具体身份，不能提升为更高层级的出版类型。

有明确撤稿等影响推荐的状态证据时，不静默推荐该记录；保留引用对象和状态提示。无法确定唯一合适版本时，推荐可以为空，并给出原因。默认只提供一个建议，不等于无论证据如何都必须生成建议。

### 推荐记录与更新

文章保存推荐版本 ID、推荐理由、相关证据、计算时间及规则版本。新增可靠发表记录、版本关联改变、关键出版状态变化或推荐规则更新时重新判断。仅新增重复来源、补全页码或调整显示格式时，推荐通常保持不变。

推荐是来源事实上的系统派生选择，不是来源原始事实，也不是作者偏好。作者在某次任务中选择保留另一版本，不改写共享推荐；推荐更新也不回写历史任务。

### 与当前输入的关系

| 当前引用情况 | 主要呈现 |
| --- | --- |
| 已是推荐版本，核验无冲突 | 已核实；仅在有依据时提供补全或规范化建议。 |
| 已是推荐版本，但字段错误 | 推荐该版本的修正记录及对应字段证据。 |
| 准确指向另一个有效版本 | 当前引用有效；另说明存在默认推荐版本并给出切换建议。 |
| 文章确定，但输入混合多个版本 | 明确混合问题；只有推荐关系可信时才给出一致的整条建议。 |
| 文章身份未决或版本关系不明 | 保留候选与证据，不执行确定性替换。 |

仅凭 Bib 无法判断正文是否依赖预印本的特有内容。版本建议须允许作者保留原引用；“当前版本可核实”和“默认推荐另一个版本”可以同时成立。


## 06  核查执行、知识复用与历史证据

> 每次任务都走同一流程：解析输入 → 匹配知识库 → 检查证据覆盖与时效 → 必要时检索 → 更新来源和版本 → 核验当前输入 → 生成建议与报告。

### 按需检索，不重复做已完成的信息获取

按 DOI、官方 ID、规范化题名与作者等匹配已有知识。命中后判断本次待核字段是否有依据、版本发现是否需要更新、是否存在冲突。已有证据足够时直接比较本次输入；缺信息时只补查相关来源和字段。

| 已有知识的情况 | 本次行为 |
| --- | --- |
| 对应版本字段充分且证据有效 | 复用源内容与整合记录；针对本次 Bib 重新形成结论。 |
| 身份确定，但待核字段不完整 | 保留已有证据，只补查缺少部分。 |
| 仅有预印本，发表信息较久未更新 | 按版本发现策略重新查找正式版；命中预印本不代表发现工作结束。 |
| 冲突、歧义或关键状态可能变化 | 有针对性地补充证据；不足时保留未决项。 |
| 上次无结果或请求失败 | 无结果采用较短缓存；失败只作退避信息，不记为不存在。 |

### 知识库与查询缓存分开理解

文献知识库长期保存文章、版本、源内容及有依据的派生关系。查询缓存按来源、接口、规范化参数及适配器版本复用请求结果。两者可使用同一存储系统，不需要分拆成独立服务。

时效按信息类型配置：稳定书目字段、正式版发现、出版状态和无结果查询分别处理。证据过期不等于事实变假；需要刷新而无法刷新时，明确显示旧证据与受限覆盖，不伪装成实时验证。首次实现不依赖跨任务“通过结论”缓存。

### 持续写入与历史保护

来源获取成功后即可持久保存，不必等整库完成。只有确认归属的内容才参与版本整合；单条失败不撤销其他条目已得到的事实。并发处理相同来源记录时应去重、幂等，避免重复创建文章或版本。

每份报告固定引用当时使用的源内容快照、版本整合修订及推荐依据。任务开始后知识可能继续更新，各条目需记录实际采用的证据修订；报告形成后不自动跟随最新知识变化。

删除任务不默认删除共享文献知识；清除查询缓存不删除历史证据。清理知识或全部数据时明确说明作用范围与历史依赖，不留下无法查看依据却仍宣称“已验证”的报告。


## 07  界面与辅助能力

主导航收敛为“核查、文献知识库、设置”。历史任务归入核查；数据源、成本和日志作为支撑能力，不为每个 Provider 或会议创建独立业务入口。

### 核查工作台

| 区域 | 展示与交互原则 |
| --- | --- |
| 顶部任务概览 | 文件、进度、明确冲突、尚未核实和未完成条目；成本和缓存命中放次级位置。 |
| 主列表 | 一个输入条目一行，不因命中多个来源而展开多行。支持搜索、问题筛选与查看全部条目。 |
| 条目详情 | 先展示主要结论与默认建议，再展示字段差异、版本关系和证据；完整调用过程按需展开。 |
| 字段对照 | 字段、原值、建议值、判断类型与证据。区分当前版本纠错和版本切换，避免把建议当成错误。 |
| 结果操作 | 复制字段或建议条目、打开来源、导出报告；不要求作者完成一组“采纳／已处理”动作才能结束。 |

界面优先用布局、分组和必要状态表达关系，避免重复的二级标签、解释性副标题和层层卡片。不同来源的细微差异收在版本详情中，默认只给作者一个整合后的建议。

### 文献知识库视图

支持按题名、作者、DOI 或来源 ID 查找文章。文章详情显示推荐版本与已知版本；版本详情显示整合字段、来源列表、获取时间和冲突依据。它是知识查询与诊断入口，不要求作者手动维护所有文章或逐一整理来源。

界面不把用户任务中的 citation key 当作文献全局身份，不展示跨任务的采纳、忽略统计作为文献可信度，也不通过作者点击某个版本来修改共享推荐。

### 设置与运行记录

集中管理来源启停、凭据、连接测试、模型配置、超时、并发、请求限流、查询预算与信息时效。作者可设置访问范围，但不应被迫逐条决定去哪个网站检索。

调用记录保留来源、状态、耗时、重试、缓存命中，以及能够取得的 usage 和费用信息；价格快照与调用结果绑定，未知价格不记为零。日志默认脱敏，细节按需查看。

预算或权限不足时保留已完成部分，并给出未完成原因；来源失败不阻塞其他来源。模拟数据、离线样例与人工未核验材料必须明确标识，不能显示成真实在线核验。


## 08  数据源规划与全新实现边界

### 数据源是支撑，不是独立业务模块

统一支持候选检索、按标识符取记录、获取权威书目信息与来源追溯。来源配置表达其能力，不要求每个来源都具备全部操作。以下是接入规划，不表示接口、授权或当前实现已经核验。

| 来源类别 | 拟接入或复用对象 | 承担的作用 |
| --- | --- | --- |
| 注册与预印本 | Crossref、arXiv；按需补充 DataCite。 | 确认标识符及版本元数据，保留直接证据。 |
| 通用候选发现 | OpenAlex、Semantic Scholar；扩展可接入 DBLP。 | 发现候选、其他版本与权威来源线索。 |
| 官方论文集 | 优先以 ACL Anthology、PMLR 做样板；后续扩展其他平台。 | 确认具体发表身份，生成可靠的正式版建议。 |
| 补充或授权来源 | Google Scholar 第三方路径、WoS、Scopus、CNKI 等按需评估。 | 补充覆盖，不作为基本核查的前置条件。 |

按出版平台接入，不为每个会议硬编码一套流程。针对包含投稿、录用与正式出版不同阶段的平台，分别确认状态；搜索摘要、投稿页和最终论文集不能互相替代。具体接口、获取方式、额度和使用条件在实现阶段另行验证。

### 全新实现约束

**本次项目采用 greenfield remake**。不使用旧项目的业务模块、前端组件、SQL 表、API 约定、缓存键、任务状态枚举或配置格式作为实现前提；不建设旧数据迁移脚本、旧接口兼容层或旧 UI 过渡页。技术栈可按新设计选择，但必须落实文献身份、源内容证据、推荐版本及整库安全导出的关键约束。第三方开源基础库可正常使用，不受“旧代码不复用”限制。

建议采用 React + TypeScript + shadcn/ui 风格前端、Python FastAPI + `uv` 后端，以及单实例 SQLite 持久化。技术选择不是旧仓库继承关系，也不要求微服务、向量数据库、复杂事件系统或多用户账号。新数据表围绕独立核查任务与文章、版本、源内容三层设计；所有事实关联保持可追溯、可纠错、幂等写入。

原始 Bib 是不可信输入；来源网页也是不可信数据。只按必要范围外发字段，密钥只在后端保存，禁止执行输入中的命令或来源页面中的指令。所有建议须能定位到具体来源记录或明确标记为无法确认。

仅发送查询所需字段，默认不把整库交给第三方。密钥只在后端使用；上传大小、解析资源及外部 URL 获取设边界；不执行 Bib 中的命令，也不执行来源页面中的指令。缓存与源内容的保存、展示范围遵守对应来源授权。

### 交付顺序

第一阶段从空白工程建立基础应用、整 Bib 解析、独立任务执行、不可变原件、规范化来源记录与安全接口。第二阶段建立文章—版本—源内容知识库、同版本归并、字段来源溯源、文章推荐版本，贯通当前版本核验与书目校订。第三阶段实现 ACL Anthology / PMLR 的正式版发现以及完整的任务列表、任务详情、引用详情、知识库和设置页面。第四阶段补齐整库校订预览与新文件导出、异常恢复、真实来源验收和端到端回归。

所有阶段都以**新数据模型与新接口**为唯一契约，不从旧数据库读取、不实现旧接口映射，也不为了展示旧结果保留任何旧逻辑。


## 09  验收场景与本版决策摘要

验收以作者能否得到正确、有依据、可操作的整库结果为准。先检验误合并、错误替换和证据污染，再检验召回覆盖与调用成本。

| 场景 | 必须得到的结果 |
| --- | --- |
| 完整文件与异常条目 | 原文件字节不变；所有条目有去向；解析失败和不支持项明确报告。 |
| DOI 指向另一篇论文 | 报告 DOI 归属冲突；继续定位原条目，不整条替换成另一篇论文。 |
| 多源仅有小幅表达差异 | 归入同一版本；保留源内容；等价表达不制造错误或新版本。 |
| 同版本的互补字段与冲突 | 有依据地补全；冲突可追溯；作者列表不做集合并集。 |
| 预印本与正式会议版 | 同文章、不同版本；推荐可替代的正式版；不混用年份、DOI 与出处。 |
| 有效预印本输入 | 保留“当前引用有效”结论；正式版作为建议，不报成原字段错误。 |
| 扩展论文、同名候选或聚合混合记录 | 不强制合并或替换；来源字段按归属处理，不复制到错误版本。 |
| 再次上传，改 key 或改字段 | 新任务独立核查；复用已有证据；不继承旧的通过结论或用户选择。 |
| 新发表记录与旧报告 | 更新当前知识与推荐；旧报告及所用证据不被悄悄改写。 |
| 失败、无结果、预算耗尽 | 分别显示；不转化为论文不存在或已验证；保留已完成内容。 |
| 知识清理与用户选择 | 采纳、忽略不进入事实层；删除任务与清理知识分别说明范围。 |

### 评估与交付物

使用脱敏或合成的代表性 Bib 样本，检查字段建议准确性、正确条目误报、版本误合并／误拆分、错误版本替换、未决比例与证据可追溯性；同时记录调用量、缓存命中和耗时。不预设未经测试的准确率或节省比例。

交付应包含完整的新源代码、配置示例、依赖锁文件、建库/迁移版本管理（仅服务未来新版本演进）、自动化测试、真实来源验收记录和使用说明。**不交付旧系统迁移方案、兼容层或旧代码依赖清单。** 离线样例只能验收流程，不能替代真实接口与来源质量验证。

### 本版决策摘要

> 两个核心业务：引用核查、书目校订。一个统一核查入口：再次上传即新任务。一个共享文献知识库：文章 → 版本 → 源内容。同版本归并，多版本关联，默认推荐其中一个整合版本。用户选择与本次核查结论留在任务侧，原始 Bib 始终只读。

适用说明：本稿是全新实现的产品与领域模型基线，具体数据实体、接口和验收条件参见同包的开发说明与领域契约。后续实现应从该边界拆解任务，不能通过接入更多来源替代身份匹配、证据归并与推荐一致性的验收。

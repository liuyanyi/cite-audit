# 下一阶段：真实 API 验收

此步骤尚未执行。离线 mock/MockTransport 测试不能证明用户账号权限、真实召回或实际字段准确率。

## 准备

1. 在本机启动应用，先用 demo.bib 完成离线演示。确认页面有“离线演示”标识、原文件下载字节不变。
2. 在本地 `.env` 或设置中填三组配置：兼容模型的 Base URL/key/model；有 Search/Fetch 权限的 DeepSeek key；Semantic Scholar key/实际获批速率。不要在聊天或 Git 提交密钥。
3. 建议先设置单条预算 12、任务预算 40，用 3–5 条可公开查询的脱敏文献。API费用未在应用中计算，请参考供应商控制台实际账单。
4. 设置内逐个测试 Crossref、arXiv、S2、DeepSeek、模型。独立记录鉴权、连通性和 JSON/Fetch 能力；失败只表示该能力尚未通过。

## 最小真实样本

- 一条已知正确的期刊条目，含 DOI 与卷期页码。
- 一条同名/近似论文并带错误 DOI，确认不会被替换成另文。
- 一条已明确发表、标题发生变化的 arXiv 预印本，包含可验证版本关系。
- 一条没有 DOI 的书籍/学位论文，以及一条文章号文献。
- 一条中文文献，分别 CNKI 关闭、中文、开启；再测试实际下载的 CNKI 题录格式。

每条人工标注参考值和来源。首次在线完成后下载报告，再上传同文件，检查 API 调用数为 0 或仅必要新分支。只改一个年份/作者字段，确认只重新比对对应条目。启用 CNKI 时，其他来源不重新联网。刷新一条后旧报告内容必须保持不变。

## 异常和结果记录

通过小预算触发预算耗尽；在可控测试配置下验证鉴权失败/429/超时和模型无效 JSON。不得故意滥发真实请求来制造限流。中途取消、关闭浏览器后刷新、重启服务，观察队列恢复。密钥不应出现在 Network 响应、JSON 报告、缓存原响应及普通日志中。

记录：字段建议准确性、正确条目误报率、版本误匹配、未解决比例、缓存命中、实际外部请求/重试/重定向数量、模型 token、耗时。真实精度和费用在当前交付中均未测量，不引用离线 fixture 的通过率作为真实准确率。

## 停止条件

任何错误文献被唯一确认、错误版本被推荐、无证据事实修正、明文 key 外泄、忽视 Retry-After/预算或原文件被改变，立即停止真实批量测试。保留脱敏报告和问题条目，修复回归后再继续。模型网页线索仍需人工核对；真实 CNKI 全库覆盖不属于验收承诺。

浏览器视觉 QA 尚需在实际运行电脑补验：桌面/窄屏、上传后刷新、长标题/中文、错误提示、重复点击、对话框 Escape/关闭、取消/重试、前进/后退以及复制和下载。

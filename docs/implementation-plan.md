# BibTeX 引文校验工作台：需求与实现方案

版本：1.0

日期：2026-10-24

状态：用户已确认产品方向；本文作为后续云端 agents 的开发与验收依据。

## 1. 开发交接与授权边界

本项目是独立的引文校验工具。当前文档保存在论文仓库中，仅作为交接材料，不代表应将应用耦合进论文构建系统。后续开发优先使用明确指定的独立项目或独立应用目录，遵守目标仓库的 AGENTS.md。

- 当前任务仅保存方案，不编写应用代码、不部署、不调用用户的付费 API。
- 后续收到实现任务后，以本文确定的需求为基础完成实现、测试和运行说明；技术细节可作合理选择，实质范围变化需记录并确认。
- 不修改论文正文、参考文献源文件、论文规划或现有应用；保留工作区中的无关修改。
- 上传文件是检查输入。系统不得回写、覆盖或自动修改用户的原始 `.bib`。
- 密钥由运行环境或用户配置提供，不提交真实密钥，不要求用户将密钥写入聊天或代码。
- 云端开发环境与应用生产部署是两回事；本文不授权公开部署、上传真实文献库到第三方托管平台或建立定时任务。
- 本文中的 API 能力来自文档调研，尚未用用户密钥实测。开发时核对最新接口契约、额度与服务条款，不把调研结果视为已完成集成。

## 2. 产品目标与非目标

用户上传 BibTeX 文件，系统逐条核验书目信息，寻找 DOI 和正式发表版本，在页面展示问题、修正建议和证据。用户手动修改本地 BibTeX，再次上传进行增量复查。

### 2.1 必须实现

1. 解析文件中的全部文献条目并报告解析问题。
2. 核验标题、作者、年份、出处、卷、期、页码或文章号及标识符。
3. 查找 DOI，核验其归属，展示可点击的 DOI 链接。
4. 为 arXiv 预印本寻找正式发表版本并给出有依据的替换建议。
5. 可选 CNKI 补充检索。
6. 字段级差异、建议值、证据链接和未解决原因。
7. 持久缓存、任务恢复、重复查询合并和重新上传后的增量复查。
8. 保持三组主要 API 配置：大模型、DeepSeek 搜索与 Fetch、Semantic Scholar。

### 2.2 首版非目标

- 不自动编辑原 BibTeX，不自动应用修正。
- 不检查文献是否支持论文正文中的具体论断；该功能需要正文和原文证据。
- 不默认下载论文全文，不实现全量 CNKI 数据抓取。
- 不复刻 CiteANCHOR 的完整 benchmark 管线，不承诺其论文中的准确率。
- 不要求向量数据库、独立重排服务、多模型投票或多搜索供应商。
- 不将多用户账户、公开部署或定时监控列为首版必需项。

## 3. 方法原则

参考 CiteANCHOR 的来源发现、字段证据核验和来源恢复思想，分别判断：原引文是否正确、原文献能否唯一确定、是否存在可替换的正式发表版。

- 相似论文只能成为候选，不能直接作为正确答案。
- DOI 是强线索，但输入 DOI 可能错误，必须与标题、作者交叉核验。
- 数据库缺少字段不等于原字段错误；未检索到不等于文献不存在。
- 请求失败、限流、无结果和证据不足必须区分。
- 模型只能根据已获取证据提出事实性建议，不凭记忆补 DOI、作者、出处或页码。
- 每项事实性建议引用具体证据记录。模型自报置信度不能作为唯一决策依据。
- 来源冲突应显式呈现。不得从不同文献或不同版本拼成一条貌似完整的记录。
- 保留证据来源链，多个聚合网站复制同一记录不算独立交叉验证。

## 4. UI 与用户流程

主要流程：上传 → 查看进度 → 筛选问题 → 查看证据和建议 → 手动修改本地文件 → 再上传复查。

| 区域 | 必需功能 |
|---|---|
| 上传区 | 上传 `.bib`、文件名、条目数、解析错误、CNKI 选项 |
| 任务概览 | 进度、完成数、问题数、失败数、缓存命中、API 调用统计 |
| 文献列表 | citation key、标题、年份、主要问题、DOI 与版本状态 |
| 条目详情 | 原始条目、字段对照、正式版候选、证据与查询记录 |
| 历史任务 | 查看历史上传与结果，关联后续复查 |
| 设置 | API 配置及独立连接测试、预算、缓存管理 |

列表支持按 citation key 或标题搜索，按字段冲突、缺 DOI、可升级、证据不足、失败和中文文献筛选。

详情表至少包含：字段、原值、建议值、判断类型、证据链接。支持复制字段值、复制建议的单条 BibTeX、打开来源、刷新当前条目。当前版本修复与正式版替换应分开展示。

复制建议条目时保留 citation key、必要的大小写保护、中文与 LaTeX 转义及不冲突的自定义字段。仅生成建议，不触碰原文件。批量改写或导出修改后的整库不是首版验收要求。

页面随任务逐条更新，浏览器刷新后恢复进度。手动刷新应说明将重新查询哪些来源，避免无意全量调用。

## 5. 状态模型

| 维度 | 状态 |
|---|---|
| 文献身份 | 唯一确定、多个候选、未找到、证据不足 |
| 字段核验 | 一致、存在冲突、可补全、部分未验证 |
| DOI | 已核验、缺失待查、归属冲突、未找到、查询失败 |
| 发表版本 | 已是正式版、发现正式版候选、未发现正式版、关系不明 |
| 执行 | 排队、查询中、完成、部分完成、失败、取消 |

字段判断区分错误修正、信息补全、格式规范化、版本升级、无法核验和不适用。可选字段缺失不自动算错误。

汇总状态由各维度派生，不能掩盖未验证字段。保留候选和证据，即使最终无法确定唯一来源。

## 6. 校验流水线

### 6.1 解析与本地检查

- 使用真正的 BibTeX 解析器，不用正则代替完整解析。
- 处理字符串宏、交叉引用、注释及常见 BibTeX/BibLaTeX 字段；无法处理时明确报告，不静默丢失。
- 保留原始文件与条目文本快照，检查重复 citation key、语法错误、关键字段缺失及重复文献候选。
- 无效条目不应阻塞其他可解析条目。
- 为匹配生成规范化形式，但不改变展示原文。缺失、空值、未提供与无法验证分开处理。

### 6.2 缓存与标识符查询

先查缓存，再按 DOI、arXiv ID 等查询元数据。DOI 指向其他标题或作者时，报告归属冲突，继续用原条目其他信息找候选，不直接覆盖。

### 6.3 候选发现

先查询 Semantic Scholar 等结构化来源，证据不足时调用 DeepSeek Search/Fetch。查询策略从完整标题开始，再结合作者、出处，必要时放宽疑似错误字段。每条设置调用上限、超时及停止条件。

启用 CNKI 后按配置补充检索。对书籍、学位论文等非期刊类型使用相应字段规则，不因学术索引缺失而判错；不支持的类型明确显示支持范围。

### 6.4 身份与字段核验

确定性规则负责标识符、规范化字符串与数值比对。模型负责复杂名称变体、候选消歧、网页抽取与解释。结构化模型结果必须通过模式校验，证据 ID 必须真实存在。

重点处理：作者顺序与缩写、在线发表与卷期年份、期刊/会议别名、文章号与页码、中文和英文题名、LaTeX 特殊字符。元数据的来源权威性按字段与版本判断，不设盲目的全局覆盖顺序。

### 6.5 生成结果

生成字段差异、建议值、来源、判断理由及未决项。用程序从经过验证的结构化字段生成建议 BibTeX，避免让模型自由重写整个文件。

## 7. arXiv 与正式发表版本

查询顺序：arXiv 的发表 DOI/journal_ref → Semantic Scholar 关联记录 → 出版商或会议官网搜索 → 版本关系核验。

| 证据情况 | 处理 |
|---|---|
| 明确关联同一工作正式版 | 展示完整替换建议和关联证据 |
| 标题变化但有明确关联 | 展示变化字段及依据 |
| 仅标题作者相似 | 保留候选，待确认 |
| 扩展版、后续工作或多个版本 | 不强行选择唯一替代 |
| 未找到正式版 | 保留预印本，记录查询范围与时间 |

正式版建议整体更新条目类型、标题、作者、年份、出处和 DOI，避免混合版本。保存原 arXiv ID、具体版本号及原记录。只有 BibTeX 无法判断正文是否依赖预印本特有内容，实质版本差异需在 UI 中提示用户确认。

## 8. DOI 绑定

每条执行 DOI 查找及核验，不承诺所有真实文献都有 DOI。

验证层次：格式 → 登记/解析 → 文献身份 → 所选版本。短暂解析失败不直接证明 DOI 无效。

- `doi` 存标识符，UI 生成正确编码的 `https://doi.org/...` 链接。
- arXiv 自身的 `10.48550/arXiv.…` DOI 与正式发表 DOI 分开记录。
- 不能把 CNKI 编号、URL 或其他标识符当作 DOI。
- 未找到 DOI 时保留官方来源链接并显示状态，不生成不存在的 DOI。

## 9. CNKI 可选补充检索

模式：关闭 / 仅中文条目 / 全部条目。默认关闭，中文识别只是路由线索，用户可以覆盖。

第一版复用 DeepSeek 查询：完整标题加 `site:cnki.net`、标题核心部分与作者加站点限制、DOI 加站点限制。读取命中页面，提取书目信息。

- 功能名明确为 CNKI 公开网页补充检索，不声称覆盖 CNKI 总库。
- 搜索摘要是线索，不足以确认全部字段。
- 未命中显示“公开网页检索未命中”，不显示“CNKI 未收录”。
- 页面读取失败显示“候选待核验”，不能当作没有该文献。
- 提供打开 CNKI 入口、复制查询条件、粘贴详情链接或题录文本、导入题录文件的补充路径。
- 人工导入记录标注来源方式，不能显示成系统已在线核验。
- 导入格式根据真实样本实现并明确列出支持格式，避免假设 CNKI 的所有导出版本格式相同。
- 首版不依赖逆向内部接口；正式机构接口待获得文档和权限后再适配。

## 10. 缓存与增量复查

缓存必须持久化，重启后仍有效，不只是进程内字典。

| 缓存层 | 内容 | 缓存键主要组成 |
|---|---|---|
| 请求 | API 原始响应 | 提供方、接口、规范化参数、适配器版本 |
| 页面证据 | 页面内容与抽取结果 | 规范化 URL、内容摘要、抽取器版本 |
| 文献记录 | 各来源元数据与版本关联 | DOI/arXiv/来源 ID 及确认后的映射 |
| 校验结果 | 字段判断、建议、证据引用 | 条目语义摘要、证据版本、规则与模型配置版本 |

不得仅按 citation key、文件名或标题合并文献。语义摘要排除无关空白等格式变化，但保留会影响核验的字段；原始文本单独保存。

建议初始有效期，可配置：已发表元数据 180 天、常规搜索 30 天、未发现正式版或文献/DOI 的负结果 7 天。网络错误仅短期退避，不作为负结果。人工导入题录持久保留，历史检查保留当时证据。

复查规则：

1. 未变条目且证据有效：复用结果。
2. 改过条目：优先用现有证据重比对，确有需要才联网。
3. 新条目：正常检查；删除条目不进入新任务。
4. 新启用 CNKI：只补跑该来源。
5. 规则或模型配置变化：重新计算受影响判断，尽量复用原始证据。
6. 同一时刻相同外部查询合并执行。
7. 刷新产生新证据版本，不篡改历史任务的依据。

UI 显示获取时间、过期状态及缓存来源，提供刷新当前条目、刷新过期结果。缓存删除与历史任务删除的关系需明确，避免删除证据后留下无法查看的“已验证”结论。

## 11. API 配置与调用控制

| 配置组 | 必需配置 | 可选配置 |
|---|---|---|
| 大模型 | Base URL、API key、模型名 | 超时、并发、输出限制 |
| DeepSeek Search/Fetch | API key | 超时、调用预算 |
| Semantic Scholar | API key | 获批速率、超时 |

默认模型适配器可面向兼容接口实现，但不能假设所有服务的工具调用或结构化输出行为一致，应独立做能力测试。

内置公开来源：Crossref、DOI 内容协商、arXiv，必要时 DataCite。它们不增加用户维护的 key 组，但需要独立的限流、缓存和错误处理。

调研时 DeepSeek 接口为 `POST /v1/tools/search` 与 `POST /v1/tools/fetch`，位于 `https://api.deepseek.com`。Semantic Scholar 使用 Academic Graph API；速率按用户实际获批额度配置，不硬编码为无限并发。

配置页面独立测试鉴权、接口能力和网络连通性。记录调用次数、缓存命中、延迟、模型 token；费用无法准确计算时标注估算，不伪造精确金额。单条和整任务都应有调用预算，耗尽时保留部分结果。

429、超时、5xx 使用有限重试和退避，遵守 Retry-After；鉴权错误不无限重试。来源失败不阻塞其他来源。

## 12. 建议架构与数据模型

首版建议单实例 Web UI + 后端 API + 持久任务队列 + SQLite + 本地证据文件。默认面向本地单用户运行，云端 agents 负责开发与测试；目标运行环境应由 README 说明。

模块分离：BibTeX 解析、候选发现、文献身份匹配、版本关系、字段核验、建议生成、来源适配器、缓存和任务调度。

主要实体：

- Upload：文件摘要、原始快照、上传时间。
- Task / TaskEntry：任务配置、进度、条目快照、复查关联。
- SourceRecord：来源原始记录及提取字段，不混合覆盖。
- Work / PublicationVersion：已确认文献身份与各版本关系。
- Evidence：来源 URL/标识、获取时间、内容摘要、提取方式。
- FieldAssessment：原值、建议值、判断类型、证据 ID、规则版本。
- QueryCache / VerificationCache：缓存键、有效期、响应与结果版本。
- ProviderCall：脱敏后的调用状态、耗时、计数和重试信息。

条目级持久任务支持取消、重试和进程重启恢复；数据库写入应具备事务与幂等性。首版无需 Redis，若以后增加多实例再更换队列和数据库。

## 13. 数据保护与工程约束

- Key 仅后端读取，日志与错误信息脱敏，提供 `.env.example`，真实 `.env` 与上传文件/缓存不提交 Git。
- 上传设置文件大小、条目数和解析资源限制；不执行 BibTeX 中的 LaTeX 命令。
- 用户链接只允许受控 HTTP(S) 获取，限制重定向、响应大小和内网目标，防止 SSRF。
- 来源页面是数据，不是指令；模型不得执行页面中的操作要求。
- 原始文件、缓存和任务历史提供明确的删除操作及说明。
- 对第三方只发送完成查询所需的条目或字段，避免默认把整库发给模型。

## 14. 实施顺序与交付物

| 阶段 | 交付 |
|---|---|
| 1 | 上传解析、任务存储、列表和详情、原文件保护 |
| 2 | DOI/Crossref/Semantic Scholar、字段差异与证据 |
| 3 | DeepSeek Search/Fetch、模型消歧、arXiv 正式版建议 |
| 4 | 缓存与增量复查完善、CNKI 补充、人工题录导入 |
| 5 | 实际样本验证、异常恢复、配置与运行文档 |

后续实现交付应包括：源代码、依赖锁定、示例配置、数据库迁移、脱敏测试样本、自动化测试、完整启动命令、API 配置步骤、缓存管理和故障排查说明。提供离线 mock 以便没有密钥时开发和演示；mock 结果必须显式标注，不能伪装成真实核验。

## 15. 验收标准

必须通过以下场景：

1. 上传与检查后，原始 BibTeX 字节内容不变。
2. 所有可解析条目进入任务；语法错误和不支持结构明确报告。
3. 每项事实性修正可追溯至证据，无证据字段保持未验证。
4. 错误 DOI 不导致整条替换为另一篇论文。
5. 正确条目不因缺失可选字段、作者缩写或等价格式被误判为错误。
6. 相似论文、扩展版和多候选不会被强制选为唯一替代。
7. 正式版建议不混合不同版本的元数据。
8. 无 DOI 的真实文献可保留，查询失败不会被解释成无 DOI。
9. 同一文件在有效缓存期内再次检查，不重复相同外部查询；用调用计数验证。
10. 只修改一个条目时，仅重算受影响部分；已有证据足够时不联网。
11. 重新启用 CNKI 只补充该分支；关闭时不发 CNKI 定向查询。
12. CNKI 无搜索结果不显示成“未收录”；人工题录有明确来源标记。
13. 限流、断网、鉴权失败和模型无效输出可恢复且不产生虚假通过结果。
14. 浏览器刷新、后端重启后任务与缓存仍可恢复。
15. API key 不出现在前端响应、源码、结果报告和普通日志中。

样本集应覆盖：正确条目、错误标识符、缺作者、年份差异、文章号、中文文献、标题变化的正式版、无 DOI 文献、不可唯一恢复文献、宏/交叉引用、重复 key 和 malformed BibTeX。报告字段建议准确性、正确条目误报、版本误匹配、未解决比例、缓存命中、实际调用量及耗时，不预设未经测量的性能承诺。

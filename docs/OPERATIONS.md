# 本地运行与交付边界

## 安装包

源码运行先构建前端，再启动后端。构建 wheel 同样先执行 `frontend` 下的 `npm ci`、`npm run build`，然后回到根目录执行：

```sh
uv build --wheel
uv run --locked python scripts/check_wheel.py dist
```

wheel 包含 `cite_audit/static` 中的前端产物。用于其他机器时，可创建独立环境并安装已构建的 wheel：

```sh
uv venv --python 3.12
uv pip install ./cite_audit_remake-0.1.0-py3-none-any.whl
uv run --no-project cite-audit --data-dir ./local-data
```

请将文件名替换为实际产物。源码开发统一用 `uv sync --locked`；wheel 安装针对分发产物，不另外维护 requirements 文件。

## 存储与备份

应用在数据目录中建立 `cite-audit.sqlite3`。原始上传、快照、任务与来源事实分别持久保存。SQLite 使用 WAL；运行期间可能出现 `-wal`、`-shm` 文件。

备份步骤：停止应用，复制完整数据目录，在新的独立目录恢复后启动验证。不要仅在运行中复制主数据库文件，也不要将旧版 Cite Audit 数据库直接放入此目录。本实现没有旧版迁移程序。

本地凭据在数据库中保存，读取设置接口不会返回密钥内容。磁盘本身未加密；操作系统权限、备份权限和设备安全仍由部署者管理。不要共享数据目录、上传含密钥的备份，或将真实 Bib、日志与配置提交到仓库。

## 部署范围

默认是一个进程、一个本地用户，监听回环地址。`--host` 不是公网部署方案。应用没有账号认证与多人隔离；主机白名单和请求来源检查不能代替认证。需要远程访问时，应先单独设计认证、TLS、访问限制及备份策略，再评估部署，不能直接将端口发布到公网。

## 演示、在线与验证结论

- 演示模式只匹配固定的 BERT 样例。快照、版本关系与引用结论都带演示标记，不是重新从网站获得的事实。
- 在线模式只使用实际请求返回的内容，不自动降级为演示证据。请求失败、无结果、预算耗尽和身份不确定分别保留。
- Crossref/arXiv 提供定向检索；OpenAlex、Semantic Scholar 用于候选发现；ACL/PMLR 提供官方记录解析。官方记录查询不等于全库索引，不能保证发现全部正式发表版本。
- 来源配置状态与连接状态分开。网络、配额、API key 或服务策略变化都可能使调用失败。设置页中的来源测试会发起真实请求。
- 模型默认关闭。当前实现提供 MMSP 配置、目录价格、连接测试及调用审计，尚未把模型接入任务检索规划、候选消歧或网页抽取。开启配置不代表任务已使用模型；付费连接测试必须由用户显式触发。
- 自动化离线测试验证软件行为，不证明文献判断在真实数据上的准确率。若没有真实来源实测记录，不得称已完成在线验收。

## 核查与导出语义

当前引用先对应具体出版版本，再与该版本的来源字段比较。推荐版与当前版可以年份、DOI、出处不同，这些是版本变化，不自动计作当前引用错误。

同版本字段冲突保持可见；跨版本不能拼出一条混合书目。整体切换使用目标版本的完整提案。服务器从已冻结的提案生成导出，不接受客户端任意提交一组“已验证”字段。

导出预览不覆盖原始文件。确认生成时核对预览的输出 hash，若内容已变化则拒绝，要求重新预览。新文件、选择记录和变更清单属于该次任务，不回写为共享知识。

## 故障排查

- 首页提示前端未构建：运行 `cd frontend`、`npm ci`、`npm run build`；从 wheel 安装时检查 wheel 是否包含 `static/index.html`。
- 前端开发模式请求失败：确认后端在 `127.0.0.1:8000`，Vite 的代理配置与实际端口一致。
- 任务未完成：查看该任务的执行状态及调用记录，区分取消、来源失败和预算耗尽。重试会新建任务，不覆盖历史报告。
- 连接测试失败：检查来源的凭据、启用状态和网络限制；不要把失败当成文献不存在。不要在问题报告中粘贴 API key。
- 重启后看不到数据：确认本次使用的数据目录和上次相同，尤其是相对路径与启动目录。
- SQLite 文件占用：停止所有使用该数据目录的应用进程，再备份或移动；不要删除运行中的 WAL 文件。
